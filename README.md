# Конфигурационное управление — практическая работа №1, вариант 5

Учебный **эмулятор командной строки UNIX-подобной ОС** на Python.
Проект выполнен по сборнику практических работ для ИКБО-13-25.
Используется консольный интерфейс (CLI) и виртуальная файловая система
(VFS), исходником которой служит каталог на компьютере.

## Требования

- Python 3.9+;
- PyYAML (зависимость перечислена в `requirements.txt`);
- Linux, WSL или macOS для запуска проверочных `.sh`-скриптов.

Установка библиотеки:

```sh
python3 -m pip install -r requirements.txt
```

## Состав проекта

```text
src/main.py             Запуск эмулятора и выполнение стартового скрипта
src/config.py           Чтение YAML и параметров командной строки
src/vfs.py              Виртуальная файловая система в памяти
src/shell.py            Реализация команд
config.yaml             Пример конфигурации
vfs/                    Примеры трёх видов виртуальной системы
scripts/                Стартовые и проверочные скрипты
tests/                  Автоматические тесты
run.sh                  Скрипт запуска
.gitignore              Исключения для Git
```

## Запуск

```sh
./run.sh
./run.sh --vfs vfs/deep
./run.sh --startup scripts/startup_stage5.txt
./run.sh --config config.yaml --vfs vfs/minimal
```

Можно также запустить `python3 src/main.py` из каталога проекта.
Чтобы увидеть список параметров: `./run.sh --help`.

Параметры:

| Ключ | Назначение |
| --- | --- |
| `--config ПУТЬ` | YAML-файл конфигурации |
| `--vfs ПУТЬ` | Физический каталог VFS |
| `--startup ПУТЬ` | Файл стартовых команд |

Конфигурационный файл содержит два поля:

```yaml
vfs_path: vfs/demo
startup_script: scripts/startup_demo.txt
```

Аргументы командной строки имеют приоритет над значениями YAML.
Если путь задан в YAML, он считается относительно папки YAML-файла.
Путь, заданный аргументом командной строки, считается относительно
текущего рабочего каталога. `run.sh` переходит в каталог проекта.
При запуске печатаются все действующие настройки.

## Как работает VFS

Эмулятор читает файлы и каталоги из заданной папки, затем хранит
их содержимое и структуру в памяти. Изменения **не записываются**
на исходный диск. Символические ссылки при чтении содержимого VFS
пропускаются. Имена каталогов показаны в приглашении командной строки.

Примеры:

- `vfs/minimal` — минимальная структура;
- `vfs/few` — несколько файлов;
- `vfs/deep` — не менее трёх уровней вложенности;
- `vfs/demo` — обычная VFS с подпапкой `docs`.

Пути команд оболочки относятся к **виртуальной** системе, а не к
реальным каталогам компьютера. Поддерживаются абсолютные пути (`/docs`),
относительные (`docs`), `.` и `..`.

## Команды эмулятора

| Команда | Описание и пример |
| --- | --- |
| `ls [путь]` | Показать содержимое каталога: `ls /docs` |
| `cd [путь]` | Перейти в каталог: `cd docs`, `cd ..`; без пути — в `/` |
| `pwd` | Вывести текущий путь в VFS |
| `history` | Показать историю команд с номерами |
| `uptime` | Примерное время работы ОС в формате дней и часов |
| `touch файл...` | Создать пустые файлы или обновить виртуальную дату |
| `mkdir каталог...` | Создать каталоги (родитель должен существовать) |
| `exit` | Завершить эмулятор |

Строка разбивается на слова по пробелам, как требует вариант №5.
Аргументы в кавычках и дополнительные опции настоящих UNIX-команд
не реализованы: задача — создать учебный, а не полный Bash.

## Пример диалога

```text
demo:/$ pwd
/
demo:/$ ls
docs  hello.txt
demo:/$ mkdir work
demo:/$ cd work
demo:/work$ touch example.txt
demo:/work$ ls
example.txt
demo:/work$ pwd
/work
demo:/work$ cd ..
demo:/$ exit
```

При ошибках (несуществующий каталог, неправильные аргументы,
неизвестная команда) выводится пояснение, после чего REPL продолжает
работать. Стартовый скрипт выполняется последовательно, отображая
ввод и вывод команд. Строки, начинающиеся с `#`, пропускаются.

## Тесты

Запустить автоматические тесты:

```sh
python3 -m unittest discover -s tests -v
```

Проверить параметры CLI и YAML:

```sh
./scripts/check_config.sh
```

Проверить три вида VFS:

```sh
./scripts/check_vfs.sh
```

Проверить команды, успешные операции и ошибки:

```sh
./scripts/check_commands.sh
```

Запустить все проверки одной командой:

```sh
./scripts/check_all.sh
```

## Пять этапов работы

1. **REPL:** консоль, приглашение с VFS, простой парсер, заглушки
   `ls`, `cd`, `exit`, ошибки.
2. **Конфигурация:** аргументы `--vfs`, `--startup`, `--config`,
   YAML, приоритет CLI, стартовые команды и сценарии тестирования.
3. **VFS:** загрузка директории в память, несколько структур,
   отсутствие записи в исходные файлы.
4. **Основные команды:** `ls`, `cd`, `history`, `uptime`, `pwd`.
5. **Дополнительные команды:** `touch`, `mkdir`, только в памяти.

Каждый этап зафиксирован в своём Git-коммите по спецификации
Conventional/Scoped Commits. Для преподавателя важна история изменений.

## Публикация в GitHub с сохранением истории

Создать на GitHub **пустой** публичный репозиторий, затем из папки
проекта с сохранённой `.git` выполнить:

```sh
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО.git
git push -u origin main
```

При запросе авторизации использовать доступный способ входа GitHub.
**Не загружать ZIP как файл в репозиторий:** по методичке архивы
не должны находиться внутри репозитория. При загрузке отдельных файлов
через браузер история пяти коммитов не сохранится.
