# Эмулятор оболочки: вариант 5

Консольная программа на Python с восемью командами и виртуальной
файловой системой (VFS). Исходная VFS - обычная директория на диске.
Программа читает её при запуске и дальше работает только с памятью.

## Запуск и проверка

Нужны Python 3.9+ и PyYAML. Отдельная сборка не требуется.
Открыть PowerShell в папке проекта и выполнить:

```powershell
python -m pip install -r requirements.txt
.\run.bat
```

После настроек и короткого стартового примера появится `demo:/$`.
Туда вводятся команды эмулятора, например `ls` и `pwd`.
Обычные команды Windows вводятся после завершения эмулятора через `exit`.

Запуск тестов и двух проверочных скриптов Windows:

```powershell
python -B -m unittest discover -s tests -v
.\scripts\check_config.bat
.\scripts\check_vfs.bat
```

Тесты также проверяют запуск этих `.bat`-скриптов на Windows.
Без скрипта запуска можно использовать `python -B src/main.py`.
В Linux/macOS вместо `python` обычно используется `python3`.

## Параметры и YAML

| Аргумент CLI | Значение |
| --- | --- |
| `--config путь` | Файл настроек; по умолчанию `config.yaml` |
| `--vfs путь` | Исходная директория VFS |
| `--startup путь` | Файл команд перед интерактивным вводом |

Пример `config.yaml`:

```yaml
vfs_path: vfs/demo
startup_script: scripts/startup_stage2.txt
```

Значения CLI заменяют соответствующие значения YAML. Путь из YAML
считается относительно папки конфигурации, из CLI - относительно
рабочей папки. `run.bat` сначала переходит в папку проекта.
При запуске выводятся все действующие настройки.

Если конфигурации по умолчанию нет, используется `vfs/demo` без
стартового скрипта. Явно указанный отсутствующий файл - ошибка.
`startup_script: null` отключает стартовый скрипт. Значение `vfs_path`
можно опустить для выбора `vfs/demo`, но нельзя задавать пустым или null.

```powershell
.\run.bat --help
.\run.bat --config config.yaml --vfs vfs/minimal
.\run.bat --startup scripts/startup_stage5.txt
```

Стартовые файлы содержат по одной команде на строку. Пустые строки
и строки с `#` в начале пропускаются. Каждая команда выводится
с приглашением, затем выполняется. `exit` завершает весь эмулятор.

## Команды

| Команда | Действие |
| --- | --- |
| `ls [путь]` | Имена в каталоге или имя указанного файла |
| `cd [путь]` | Переход в каталог; без аргументов - в `/` |
| `pwd` | Текущий виртуальный путь |
| `history` | История сеанса с номерами, включая вызов `history` |
| `uptime` | Время работы эмулятора с запуска в формате ЧЧ:ММ:СС |
| `touch файл...` | Создание пустых файлов или обновление их времени |
| `mkdir каталог...` | Создание каталогов с существующими родителями |
| `exit` | Завершение программы |

Поддерживаются абсолютные пути (`/docs`), относительные (`docs`),
`.` и `..`. Разделитель пути - `/`. Ввод делится методом `split()`
по пробельным символам. Кавычки, имена с пробелами и опции UNIX-команд
не поддерживаются. `touch` и `mkdir` обрабатывают имена слева направо
до первой ошибки. Ошибка выводится на экран, сеанс продолжается.

## Короткая демонстрация на защите

Запустить `.\run.bat` и ввести:

```text
pwd
ls
cd docs
pwd
cd ..
mkdir work
cd work
touch first.txt second.txt
ls
history
uptime
cd /missing
exit
```

Повторно запустить `.\run.bat` и ввести `ls`: каталога `work` уже нет.
В физической папке `vfs/demo` он тоже не появился. Это демонстрирует,
что изменения VFS выполняются в памяти.

Готовые сценарии `startup_stage2.txt` - `startup_stage5.txt` в `scripts/`
проверяют этапы 2-5. Сценарий этапа 2 оставляет интерактивный ввод,
сценарии этапов 3-5 показывают ошибки и заканчиваются командой `exit`.
Сценарий этапа 4 показывает режимы `ls`, `cd`, `history`, `uptime`, `pwd`.
Сценарий этапа 5 показывает `touch` и `mkdir`, в том числе несколько имён.

## Как объяснить код

`src/main.py`:

- `main` связывает части программы.
- `run_startup` выполняет файл команд.
- `run_interactive` повторяет ввод и выполнение до завершения.

`src/config.py`:

- `read_yaml` читает и проверяет YAML.
- `load_settings` разбирает CLI и выбирает настройки.
- Вложенная `get_path` выбирает, проверяет и преобразует путь.

`src/vfs.py`:

- `__init__` один раз загружает дерево с диска.
- `_virtual_path` переводит физический путь в виртуальный.
- `resolve` проверяет компоненты пути, обрабатывает `.` и `..`.
- `contents` получает имена файлов и каталогов для `ls`.
- `touch` и `mkdir` меняют только память.

`src/shell.py`:

- `__init__` создаёт сеанс и явную таблицу команд.
- `prompt` формирует приглашение из имени VFS и текущего пути.
- `execute` разбирает строку и вызывает обработчик из таблицы.
- Методы `do_*` реализуют команды из таблицы выше.

В `VirtualFS` множество `directories` хранит пути каталогов,
словарь `files` - пути и содержимое файлов, `modified` - виртуальное
время изменения файлов. Символические ссылки при загрузке пропускаются.
В `Shell` находятся текущий путь, история и время начала сеанса.

Три примера VFS: `minimal` - один файл; `demo` - несколько файлов
с подпапкой; `deep` - три уровня каталогов и файл внутри.
Два `.bat`-скрипта в `scripts/` проверяют параметры CLI и эти VFS.
Четыре модуля в `tests/` проверяют соответствующие части программы.

В истории Git сохранены пять этапов: REPL, конфигурация, VFS,
основные и дополнительные команды. Для сдачи нужен публичный репозиторий
с этой историей. `.gitignore` исключает кэш Python и служебные файлы.
