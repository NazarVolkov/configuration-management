# Домашняя работа по конфигурационному управлению. Вариант 5

`cfg5` читает файл на учебном конфигурационном языке, разбирает его с помощью
[cpp-peglib 1.9.1](https://github.com/yhirose/cpp-peglib/tree/v1.9.1) и вычисляет константы.
Каждое объявление становится ключом TOML. Программа выводит ключи в порядке объявлений в стандартный вывод.

## Синтаксис и вычисления

- Объявление имеет вид `имя: значение`. Имена соответствуют `[a-z]+` и уникальны в пределах файла.
  Объявления разделяются пробельными символами. Пустой документ даёт пустой вывод.
- Числа соответствуют `-?(\d+|\d+\.\d*|\.\d+)([eE][-+]?\d+)?`.
  Например, `-12`, `2.`, `-.25` и `2.e+3`. Целые хранятся как знаковые 64-битные числа,
  дроби и числа с экспонентой хранятся как `double`.
- Строки заключаются в одинарные кавычки и занимают одну строку исходного файла.
  Обратная косая черта в исходной строке считается обычным символом. Файл читается в UTF-8, возможен BOM.
- Массивы записываются как `[значение, значение, ...]`. Допустимы `[]`, переносы строк, разные типы
  значений и вложенные массивы. Запятая ставится между элементами.
- `!{имя}` возвращает значение ранее объявленной константы любого типа. В операциях можно передать
  имя ранее объявленной числовой константы, число или вложенное выражение. Операнды разделяются пробелами
  или переносами строк. Поддерживается до 128 вложенных массивов или выражений.

| Выражение | Действие |
| --- | --- |
| `!{+ a b}` | Складывает два числа |
| `!{- a b}` | Вычитает `b` из `a` |
| `!{* a b}` | Умножает два числа |
| `!{max a b ...}` | Возвращает наибольшее из двух или более чисел |
| `!{sqrt a}` | Возвращает квадратный корень из неотрицательного числа как `double` |

Сумма, разность и произведение двух целых дают целое. При наличии дробного операнда вычисление выполняется
в `double`. `max` сохраняет тип выбранного операнда и при равенстве выбирает первый. Программа сообщает
о переполнении, повторном объявлении, неизвестной ссылке и неверном типе операнда.

## Сборка и запуск

Нужны Windows, Visual Studio 2022 или Build Tools с компонентом «Разработка классических приложений на C++»
и Git for Windows. При первой сборке Git получает закреплённую версию cpp-peglib в `build/deps/`.
Для этой загрузки нужен интернет. Команды выполняются в PowerShell из корня репозитория.

```powershell
.\build.bat
.\run.bat --help
.\run.bat --input .\examples\greenhouse.cfg
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run.ps1
```

| Ключ | Назначение |
| --- | --- |
| `--input <файл>`, `-i <файл>` | Прочитать указанный файл и вывести TOML |
| `--help`, `-h` | Показать справку |

Код завершения `0` означает успешное выполнение, `1` означает ошибку чтения, разбора, вычисления или вывода,
`2` означает неверную команду. Диагностика записывается в `stderr`. Синтаксические и семантические ошибки
содержат путь, строку и столбец. При ошибке разбора или вычисления TOML не выводится.

## Примеры

- **Мониторинг теплицы.** Конфигурация содержит замеры, коэффициент и поправку. Значение `adjusted`
  вычисляется как `sqrt(81) * 1.25 + (-0.5)` и равно `10.75`.
  [Входной файл](examples/greenhouse.cfg) · [Ожидаемый TOML](tests/greenhouse.toml)
- **Складской учёт.** Из `48` единиц вычитается резерв `12`. Поле `minimum` выбирает максимум
  из `8`, `20` и доступного остатка `36`.
  [Входной файл](examples/warehouse.cfg) · [Ожидаемый TOML](tests/warehouse.toml)

```powershell
.\run.bat -i .\examples\warehouse.cfg
cmd.exe /d /c ".\run.bat -i .\examples\warehouse.cfg > build\warehouse.toml"
```

## Где реализованы этапы

### Этап 1. Грамматика и синтаксический разбор

- Правила `Document`, `Declaration`, `Value`, `Array` и `Expression` задают структуру входного языка.
  [src/grammar.h](src/grammar.h#L3-L21)
- `parse_document` запускает PEG-парсер и формирует список объявлений. `read_expression` рекурсивно преобразует
  дерево cpp-peglib в модель программы, а `limit_nesting` ограничивает глубину разбора.
  [parse_document](src/parser.cpp#L53), [read_expression](src/parser.cpp#L34),
  [limit_nesting](src/parser.cpp#L14), [модель](src/model.h)
- `Test-Parser` проверяет формы числа, строки, вложенные массивы, ошибки синтаксиса и позицию ошибки.
  [tests/parser.ps1](tests/parser.ps1#L1)

### Этап 2. Вычисление констант

- `evaluate_document` запускает вычисление в порядке объявлений. `resolve_reference` ищет уже вычисленную
  константу, `evaluate_operation` выбирает операцию и проверяет типы операндов через `numeric_value`.
  [evaluate_document](src/evaluator.cpp#L89), [resolve_reference](src/evaluator.cpp#L56),
  [evaluate_operation](src/evaluator.cpp#L72), [numeric_value](src/evaluator.cpp#L64)
- `read_number` читает литералы, `calculate_binary`, `calculate_root` и `maximum` вычисляют пять операций.
  [read_number](src/numbers.cpp#L111), [calculate_binary](src/numbers.cpp#L118),
  [calculate_root](src/numbers.cpp#L131), [maximum](src/numbers.cpp#L139)
- `Test-Evaluator` проверяет все операции, вложенные выражения, ссылки и ошибки вычисления.
  [tests/evaluator.ps1](tests/evaluator.ps1#L1)

### Этап 3. Командная строка и вывод TOML

- `run` разбирает ключи. `read_input` читает файл и проверяет его кодировку через `validate_utf8`.
  `translate` связывает разбор, вычисление и вывод. Сборка и запуск доступны через командные файлы.
  [run](src/main.cpp#L57), [read_input](src/main.cpp#L30), [validate_utf8](src/main.cpp#L17),
  [translate](src/main.cpp#L40), [build.bat](build.bat), [run.bat](run.bat)
- `render_toml` формирует пары `ключ = значение`. `append_value` выбирает представление типа, а `append_string`,
  `append_number` и `append_array` сериализуют конкретные значения.
  [render_toml](src/toml.cpp#L69), [append_value](src/toml.cpp#L57), [append_string](src/toml.cpp#L9),
  [append_number](src/toml.cpp#L27), [append_array](src/toml.cpp#L46)
- `Test-Cli` проверяет ключи, коды завершения, доступ к файлам, UTF-8 и экранирование в TOML.
  [tests/cli.ps1](tests/cli.ps1#L9)

### Этап 4. Сквозная проверка на двух конфигурациях

- `Test-Examples` преобразует файлы теплицы и склада, а `Assert-TranslationFile` сравнивает весь вывод
  с эталонным TOML и проверяет код завершения и `stderr`.
  [Test-Examples](tests/examples.ps1#L1), [Assert-TranslationFile](tests/run.ps1#L30),
  [теплица](examples/greenhouse.cfg), [склад](examples/warehouse.cfg)
- `tests/run.ps1` запускает все наборы тестов и сообщает общее число пройденных проверок.
  [Точка запуска тестов](tests/run.ps1#L57)
