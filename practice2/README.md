# Практическая работа 2, вариант 5

Программа строит граф зависимостей пакетов NuGet. Настройки читаются из JSON.
Граф обходится рекурсивным DFS, выводится деревом и изображением PlantUML.
Код получения зависимостей использует только стандартную библиотеку Python.

## Быстрый запуск

Открыть PowerShell в папке `practice2`:

```powershell
.\run.bat
```

Нужен Python 3.9+. Для изображения нужен Java 17+; на этом компьютере Java
уже установлен. При первом построении изображения программа загружает
официальный PlantUML 1.2026.9 в `output`. Далее JAR используется локально.
Отдельная установка Graphviz, библиотек Python и сборка проекта не нужны.
По умолчанию откроется SVG и появится дерево пакетов A, B, C, D.

Без Java и без сети можно проверить алгоритм и получить текст PlantUML:

```powershell
.\run.bat --no-image
```

`--no-open` сохраняет SVG, но не открывает его. `--no-image` не запускает
отрисовку и не загружает PlantUML. Все результаты находятся в `output/`.
Эта папка исключена из Git. Источники данных программа не изменяет.
В Linux/macOS: `python3 -B src/main.py --no-image` из папки `practice2`.

## Настройки

```json
{
  "package": "A",
  "repository": "examples/branch.json",
  "test_mode": true,
  "ascii_tree": true
}
```

| Параметр | Значение |
| --- | --- |
| `package` | Корневой пакет |
| `repository` | Путь к тестовому JSON или URL индекса NuGet V3 |
| `test_mode` | `true`: локальный граф; `false`: настоящий NuGet |
| `ascii_tree` | Печатать ли ASCII-дерево на этапе 5 |
| `version` | Необязательная точная версия корня; иначе последняя стабильная |
| `framework` | Необязательная группа из nuspec; по умолчанию `net8.0` |

Путь к тестовому репозиторию считается относительно файла конфигурации.
Все настройки анализа берутся из JSON. Другой файл выбирается так:

```powershell
.\run.bat examples/config_cycle.json
```

В локальном репозитории имена состоят из больших латинских букв:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Стрелка A -> B означает, что A зависит от B.
Отсутствующие поля, неверные типы и имена, отсутствующий файл, неизвестный
пакет, неправильный URL, ошибки JSON, XML и сети сообщаются как ошибки.
Программа завершается с ненулевым кодом.

## Пять этапов

```powershell
.\run.bat --stage 1
.\run.bat --stage 2
.\run.bat --stage 3
.\run.bat --stage 4 --reverse D
.\run.bat --stage 5
```

| Этап | Что происходит | Основной код |
| --- | --- | --- |
| 1 | Чтение, проверка и вывод настроек | `config.py`, `main.py` |
| 2 | Получение прямых зависимостей | `nuget.py`, `repository.py`, `versions.py` |
| 3 | Построение полного графа рекурсивным DFS | `graph.py: build_graph` |
| 4 | Разворот рёбер и DFS для обратных зависимостей | `graph.py: reverse_dependencies` |
| 5 | ASCII-дерево, PlantUML и показ SVG | `visualize.py` |

Без `--stage` выполняется этап 5. Параметры печатаются только на этапе 1,
отдельный список прямых зависимостей — только на этапе 2.

## Как работает код

`main.py` выбирает этап и связывает остальные части. `run` выполняет его,
`main` разбирает аргументы и обрабатывает ошибки.

`config.py`: `load_config` читает JSON, `check_source` проверяет пакет
и источник, `check_options` проверяет необязательные настройки.

`repository.py`: `TestRepository` проверяет и читает словарь тестового
графа. `open_repository` выбирает этот класс или `NuGetRepository`.
Оба класса имеют методы `root` и `dependencies`.

`nuget.py`: `download` выполняет HTTP-запрос. `NuGetRepository` находит
`PackageBaseAddress/3.0.0` в индексе NuGet V3, читает список версий,
затем загружает XML `.nuspec`. `manifest_dependencies` извлекает прямые
зависимости выбранной группы платформы. Готовые менеджеры пакетов
и библиотеки извлечения зависимостей здесь не вызываются.

`versions.py`: `version_key` сравнивает версии по числам;
`bound_matches`, `interval_matches` и `matches` проверяют диапазон;
`choose_version` выбирает подходящую версию.

`graph.py`: `build_graph` хранит словарь списков смежности.
Вложенная функция `visit` записывает пакет в граф **до** рекурсивного
вызова для его зависимостей. Повторно записанный пакет не обходится.
Так обрабатываются циклы и общие зависимости. `print_graph` выводит
список смежности. `reverse_dependencies` разворачивает рёбра и вызывает
тот же `build_graph`.

`visualize.py`: `ascii_tree` строит текстовое дерево, `plantuml` создаёт
описание диаграммы, `get_plantuml` загружает JAR при первом запуске,
`render_svg` вызывает Java, `save_diagram` сохраняет файлы и показывает SVG.
В PlantUML используется встроенная раскладка Smetana, поэтому Graphviz не нужен.

## Что показать на защите

```powershell
.\scripts\demo.bat
.\run.bat
.\run.bat examples/config_cycle.json
.\run.bat examples/config_leaf.json
.\run.bat --stage 4 --reverse D
```

`demo.bat` работает без сети и показывает параметры, прямые зависимости,
DFS, цикл, пакет без зависимостей, обратный поиск и ASCII-дерево.
Следующие три запуска показывают изображения разных тестовых случаев.
Для D обратные зависимости — B и C, а через них A.

Пример дерева:

```text
A
+-- B
|   `-- D
`-- C
    `-- D [shown]
```

`[shown]` означает уже раскрытую общую зависимость.
`[cycle]` означает возврат к пакету в текущей цепочке рекурсии.

Три реальных пакета и изображения:

```powershell
.\run.bat examples/nuget.json
.\run.bat examples/options.json
.\run.bat examples/injection.json
```

Или одной командой: `.\scripts\visualize_three.bat`.
Нужен интернет для чтения NuGet. В примерах версии закреплены на 8.0.0,
платформа — net8.0. Сравнение со штатным NuGet описано в `COMPARISON.md`.

Короткое объяснение: «Читаю настройки из JSON, сам получаю зависимости
из nuspec, рекурсивным DFS строю граф, отмечаю посещённые узлы,
затем формирую дерево и диаграмму PlantUML».

## Ограничения учебной реализации

Поддерживаются стабильные числовые версии, минимумы `1.0.0`, точные
ограничения `[1.0.0]` и интервалы вроде `[1.0.0,2.0.0)`.
Предварительные и плавающие версии не поддерживаются.
Для зависимости выбирается минимальная подходящая стабильная версия.
Каждая версия — отдельный узел `package@version`; глобальное разрешение
конфликтов версий NuGet Restore не воспроизводится.

Группа платформы выбирается точно по имени из nuspec без автоматического
подбора совместимой платформы. Если нужной группы нет, выводится ошибка.
В тестовом режиме обратный поиск учитывает весь JSON-репозиторий.
В NuGet — только граф, загруженный от выбранного корня; цель задаётся
полным именем `package@version`. Поиск всех потребителей во всём NuGet
не выполняется. Большие графы ограничены глубиной рекурсии Python.

## Тесты

```powershell
python -B -m unittest discover -s tests -v
```

Проверяются настройки, собственное чтение NuGet, диапазоны версий,
порядок DFS, общие зависимости, циклы, обратный поиск, PlantUML, дерево
и режимы CLI. Автотесты не требуют интернета, Java или .NET SDK.
