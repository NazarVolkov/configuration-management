# Практическая работа 2. Вариант 5

ИКБО-13-25. Инструмент визуализации зависимостей NuGet на C++17.
Программа читает JSON, получает зависимости через NuGet V3 API, строит
граф рекурсивным DFS, находит обратные зависимости и показывает граф
PlantUML. Менеджеры пакетов и готовые библиотеки получения зависимостей
в анализаторе не используются. nlohmann/json и TinyXML-2 разбирают
только синтаксис JSON и XML; запросы выполняются через Windows WinHTTP.

## Сборка и запуск

Нужны Windows, Visual Studio 2022 или Build Tools с компонентом
«Разработка классических приложений на C++» и Windows SDK.
Для изображения нужна Java 8 или новее в PATH либо JAVA_HOME.
Скрипт сборки сам находит установленный компилятор MSVC.
Команды выполняются из папки работы:

```powershell
.\build.bat
.\run.bat
```

run.bat собирает программу, если build/nuget_graph.exe отсутствует.
После изменения исходников нужно повторить build.bat.
При первой сборке загружаются nlohmann/json 3.12.0 и TinyXML-2 11.0.0
в build/deps. При первой визуализации туда загружается PlantUML 1.2024.8,
совместимый с установленной Java 8. Отдельный Graphviz не нужен:
используется встроенный движок Smetana.
После загрузки зависимостей тестовый репозиторий работает без интернета.

## Настройки JSON

По умолчанию читается config.json. Другой файл задаётся первым аргументом.
Пути внутри JSON считаются относительно этого файла.

```json
{
  "package": "A",
  "repository": "tests/repository.json",
  "test_mode": true,
  "ascii_tree": true
}
```

| Параметр | Назначение |
| --- | --- |
| package | Имя пакета NuGet или заглавные латинские буквы в тестовом режиме |
| repository | URL индекса NuGet V3 или путь к тестовому JSON |
| test_mode | true: читать локальный JSON; false: обращаться к NuGet |
| ascii_tree | true: показывать ASCII-дерево на этапе 5 |
| version | Необязательная точная стабильная версия; иначе последняя стабильная |
| framework | Необязательная группа платформы nuspec; по умолчанию net8.0 |

Первые четыре поля обязательны. Логические поля принимают JSON-значения
true/false. Проверяются типы, имена, URL, существование тестового файла,
числовая версия и непустая платформа. Неизвестные поля запрещены.
Ошибка печатается как Error: ...; программа возвращает код 1.
Успешное выполнение возвращает код 0.

В тестовом репозитории каждой вершине соответствует массив зависимостей:

```json
{"A": ["B"], "B": []}
```

Имена состоят из A-Z. Все упомянутые пакеты должны иметь описание.
Файл tests/repository.json содержит ветвление, общую зависимость, цикл,
петлю, отдельный пакет и входящую связь из другой ветви.

## Этапы и команды

```powershell
.\run.bat --stage 1
.\run.bat examples/logging.json --stage 2
.\run.bat --stage 3
.\run.bat --stage 4 --reverse D
.\run.bat --stage 4 --reverse E
.\run.bat --stage 4 --reverse G
.\run.bat --stage 5
```

| Этап | Результат |
| --- | --- |
| 1 | Все настройки в формате ключ-значение |
| 2 | Прямые зависимости корневого пакета |
| 3 | Полный достижимый граф, строки «пакет -> зависимости» |
| 4 | Прямые и транзитивные потребители выбранного пакета |
| 5 | Текст PlantUML, изображение PNG и ASCII-дерево по настройке |

По умолчанию выполняется этап 5. PNG открывается в стандартном приложении.
Файлы сохраняются в output/graph_ИМЯ.puml и output/graph_ИМЯ.png.
Прочерк в списке зависимостей обозначает отсутствие связей.

Дополнительные опции:

| Опция | Назначение |
| --- | --- |
| --stage 1..5 | Выбрать этап |
| --reverse пакет | Цель обратного обхода на этапе 4; по умолчанию корень |
| --no-image | Сохранить только текст PlantUML, без Java |
| --no-open | Построить PNG, не открывая окно |
| --help | Показать синтаксис команды |

Обратный обход использует тот же рекурсивный DFS после разворота рёбер.
В тестовом режиме он видит весь JSON, включая пакеты вне подграфа корня.
В реальном режиме поиск ограничен построенным графом зависимостей корня.
Глобальный поиск потребителей по всему NuGet не выполняется.
Цель NuGet задаётся как имя@версия, например:

```powershell
.\run.bat examples/logging.json --stage 4 --reverse microsoft.extensions.primitives@8.0.0
```

В DFS вершина добавляется до рекурсивных вызовов, поэтому циклы
не вызывают бесконечный обход. В дереве [cycle] отмечает возврат
в текущую цепочку, [shown] - повторную общую зависимость.

## Тесты и три примера

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/compare.ps1 -Images
```

run.ps1 собирает проект и выполняет 30 проверок: настройки и их ошибки,
DFS, циклы, общие зависимости, обратный поиск, дерево и рёбра PlantUML.
Тесты не требуют Java и доступа к NuGet.

Три изображения можно также открыть отдельно:

```powershell
.\run.bat examples/logging.json
.\run.bat examples/options.json
.\run.bat examples/injection.json
```

compare.ps1 загружает штатный NuGet CLI 6.11.1 и выполняет nuget install
для каждого примера с версией 8.0.0, платформой net8.0 и выбором Lowest.
Пакеты распаковываются во временную локальную папку и удаляются после
проверки. Это позволяет работать и из Google Drive. Только этот отдельный
сценарий сравнения вызывает NuGet; сам C++ анализатор его не использует.
Для сравнения рёбер сценарий читает nuspec установленных NuGet пакетов,
используя версии, выбранные штатным инструментом.
Логи штатного инструмента и списки рёбер сохраняются в output/comparison.

Проверено 20.11.2026. Число вершин включает корень.

| Пакет 8.0.0, net8.0 | Вершины | Рёбра | Сравнение с NuGet |
| --- | ---: | ---: | --- |
| Microsoft.Extensions.Logging | 6 | 7 | Пакеты, версии и рёбра совпали |
| Microsoft.Extensions.Options | 3 | 2 | Пакеты, версии и рёбра совпали |
| Microsoft.Extensions.DependencyInjection | 2 | 1 | Пакеты, версии и рёбра совпали |

NuGet CLI выводит сведения об установленных пакетах, а программа
показывает связи стрелками и ASCII-деревом. Общие зависимости в графе
имеют одну вершину, в дереве их повторы помечены [shown].
В этих примерах различий в составе графа нет.

Учебная реализация поддерживает стабильные числовые версии, минимумы
1.0.0, точные версии [1.0.0] и интервалы, например [1.0.0,2.0.0).
Для каждого ребра выбирается минимальная подходящая версия отдельно.
Группа платформы выбирается по точному имени или используется группа
без платформы. Предварительные и плавающие версии не поддерживаются.
На сложных проектах возможны отличия от NuGet: штатный инструмент
разрешает конфликты версий глобально и учитывает совместимость платформ.

## Функции программы

Все объявления и типы Settings, Graph, Packages, Fetch находятся в app.h.
Graph - словарь «пакет -> массив зависимостей».

| Файл | Функции и назначение |
| --- | --- |

| http.cpp | download выполняет GET; check проверяет WinHTTP; body читает тело и HTTP-статус |
| http.cpp | Handle открывает и закрывает HTTP-дескриптор при выходе из области видимости |
| versions.cpp | stable_version, key проверяют и преобразуют числовую версию; compact убирает пробелы |
| versions.cpp | valid_bound, parse_interval, parse_range разбирают границы; matches проверяет попадание |
| versions.cpp | choose_version выбирает минимальную подходящую или последнюю стабильную версию |
| nuget.cpp | is_flat_container, package_base находят ресурс NuGet V3; lower_name приводит имя к нижнему регистру |
| nuget.cpp | select_group выбирает платформу; read_dependencies извлекает ID и ограничения из XML |

| graph.cpp | check_links проверяет JSON; load_test_graph загружает его; visit выполняет рекурсивный DFS |
| graph.cpp | build_graph строит граф; reverse_graph ищет потребителей; print_graph выводит связи |
| visualize.cpp | Tree::draw строит дерево; ascii_tree запускает его; diagram_label переносит длинные имена |
| visualize.cpp | plantuml формирует диаграмму; save_diagram пишет её; find_java находит Java |
| visualize.cpp | prepare_plantuml загружает JAR; render_png запускает PlantUML и открывает PNG |
| main.cpp | Cursor::more/value читают аргументы; parse_stage и read_option разбирают опции |
| main.cpp | parse_arguments проверяет команду; print_direct, show_graph выводят результаты |
| main.cpp | analyze выбирает операцию; run выбирает источник; wmain перехватывает ошибки |

## Оформление Git

README.md, .gitignore, src, tests и run.bat присутствуют.
Каждый из пяти этапов сохранён отдельным Conventional Commit.
Файлы короче 1000 строк, строки не длиннее 120 символов.
build и output исключены из Git: архивы, бинарники, сторонние парсеры,
артефакты сборки и изображения не отслеживаются. Настройки IDE исключены.
Правила перечня, относящиеся к другим языкам, к C++ не применяются.
Основная C++-версия находится в practice2/Main version публичного
репозитория NazarVolkov/configuration-management на GitHub.
Дополнительная Python-версия находится в practice2/Additional version.
